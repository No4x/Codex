# 教材课件全流程重构（教材 PPT → 可编辑 PPTX + 互动 HTML）

> 本文是一次**已完整跑通并验收通过**的真实项目（《电气控制技术实训》第 3 版 · 项目一
> 常用低压电器，60 页）沉淀下来的 SOP。照做即可，**不要即兴改步骤顺序**。

---

## 0 · 何时用 / 何时不用

**用**：教材配套 PPT 要重做成「可编辑、带互动、能独立带走」的一整套课件（PPTX + HTML + 文档）。

**不用**：
- 只想要一份网页版课件（无 PPTX）→ 用 `ppt-to-interactive-courseware`
- 只想要把已有 HTML 塞进 PPT → 用 `pptx-embed-html-interactions`
- 只要演讲者双屏或 SVG 仿真 → 用 `courseware-dual-screen-and-svg-sim`
- 从零创作、无教材底本 → 直接用 `ppt-master`

本 skill 是**编排层**：把上面几个 skill 串成一条有门禁、有回退、有归档的流水线，
并补上它们没覆盖的三块——**多轮迭代修订纪律**、**电气符号 GB/T 4728 口径**、**AI 配图落点审计**。

### 1.2 需求变更史（这类需求极易反复，先对齐再动手）

- **互动设计文档 → 并入 PPT**：原计划独立出《课堂互动设计.md》，后改为
  ① 互动页底部加橙色三格带（`形式`/`参与方式`/`目标`）；② 完整解析、参考答案、常见错误
  全部写进该页**教师备注**。独立文档取消。
- **配图来源口径**：`user`（教材实物照）只用于「认元件 / 看铭牌 / 对比实物」；
  **「问题引入 / 氛围」类一律可用 AI 生成**（含导入页、场景页、章首页氛围图），
  不必先找实物照。用到 AI 图的页面，页脚必须标「AI 生成示意图，非实物照片」。
- **图片偏少 → 补配图**；**符号不对 → 自绘重画**（不走网络找图，因为要可编辑、要风格统一）。

  **唯一例外**＝含 AI 生成配图的页，保留「配图为 AI 生成示意图，非实物照片」（合规标注，不可删）。
  ⚠️ 删改类指令若涉及此前定过的**合规标注**，「全删」二字要**先问清边界再动手**——
  本轮曾把 8 页 AI 免责标注一并删掉，用户要求保留，返工一轮。

## 2 · 全流程九阶段

| 阶段 | 目标 | 主要产出 | 门禁 |
|---|---|---|---|
| **P0** 源材料 | 拿到可解析的底本 | `.ppt→.pptx`、`src_text.txt`、`md/*.md`、`media/` | 图与文都可读 |
| **P1** 结构定稿 | 先定标题与页面职能再画图 | `项目X_标题结构方案.md`（L0–L4 层级 + N 页清单 + 互动/动画挂页） | 用户确认后才进 P2 |
| **P2** 工程初始化 | ppt-master 工程可校验 | `design_spec.md`（I–X）、`spec_lock.md`、`images/` | `project_manager.py validate` 通过 |
| **P3** 写 SVG | 分批手写全册 | `svg_output/*.svg`（1 页 1 文件） | 每批过早期质量门 |
| **P4** 教师备注 | 每页一段讲稿 | `notes_parts/*.md` → `notes/total.md` → `notes/*.md` | 页数与备注数 1:1 |
| **P5** 导出 v1 | 先出一版能看的 | `exports/*.pptx` → `ppt/<名称>_v1.pptx` | 真机实测抽页 |
| **P6** 互动资源 | 动画 + 互动两套 HTML | `交互动画/*.html`、`教学互动/*.html` | 真机点击 0 报错 |
| **P7** 嵌入 | HTML 挂回 PPTX | `ppt/<名称>_v2.pptx`（含 N 个嵌入对象） | **N/N 保真校验**（本项目当前 17 = 7 动画 + 10 互动） |
| **P8** 迭代修订 | 版面 / 符号 / 配图 | 逐轮升版本 | 每轮完整走一遍 P5 门禁 |
| **P9** 归档 | 索引 + 版本 + 清理 | `knowledge/INDEX.md`、`ppt/_archive/`、记忆 | 目录只留当前版 |

### P0 · 源材料

- 本机**无 pandoc**，`.ppt / .doc` 必须先经 **Office COM** 转 `pptx / txt`。
  `Presentations.Open` 首次调用会挂起 → **先杀 `POWERPNT.EXE` / `WINWORD.EXE` 再重试**，第二次成功。
- 转换脚本**不要写成 `.ps1`**（含中文路径会被 PS 5.1 按 ANSI 解码而静默失败）；
  用**内联** PowerShell 命令，输出**写日志文件**（PowerShell 工具在本机不回显 stdout），再用 Read 读。
- 成绩评定表类扫描件通常**不进 PPT**，抽成独立的《实训任务单与评分表》文档。

### P1 · 标题结构方案（关键：先文字后图形）

产出 `项目X_标题结构方案.md`：五级标题层级 L0–L4、页面职能的固定句式模板、
禁用词表、术语统一对照表、**N 页连续无重复清单**，并把互动与动画挂到具体页码。
**用户确认这一版之后才允许开画**——否则后面 N 页全要返工。

### P2 · ppt-master 工程

```bash
PROJ="<工作区>/work/p1/<工程目录>"     # 画布 ppt169 = 1280×720
```

- `design_spec.md` 必须写到 **§VIII 图片登记表** 与 **§IX 逐页 Composition** 齐备。
- `spec_lock.md` 的 images 段与 §VIII **双向闭合**（见 §5）。

### P3 · 分批写 SVG

- **一次一页、一批 10–12 页**，每批跑早期质量门。全册一次写完必然踩坑难定位。
- 页面骨架统一：白底 + 页眉左侧 6px 深蓝竖条 + 左上角章节导航 + 右上角小节标签 +
  主标题 43px + 副标题 27px + 底部 1px 分隔线 + 右下角页码；内容区 `y 220–640`，左右边距 64。
- 作者简报（契约 / 颜色字号 / 骨架 / 必避坑 / 图片分配表）留在 `work/p1/_AUTHOR_BRIEF.md`，
  分批时逐批贴给执行者。

### P4 · 教师备注

- 分片写 → 合并成 `notes/total.md`（每页一个 `# NN_短名` 标题，编号连续）→
  用 `total_md_split.py` 拆成 `notes/*.md` → `svg_to_pptx.py --with-notes` 注入。
- 成品核验：`notesSlides == slides`，且备注总字符数量级合理。

### P5 · 导出（固定三连，缺一步报 stale）

```bash
cd <工作区>/.workbuddy/../<ppt-master 安装目录>   # 或 skill 目录
PY=C:/Users/<用户名>/.workbuddy/binaries/python/envs/default/Scripts/python.exe
PROJ="<工作区>/work/p1/<工程目录>"

# 1) 质量门 —— 必须带 --json，否则 validation/svg_quality_report.json 不刷新
$PY scripts/svg_quality_checker.py "$PROJ" --canonical-authoring --stage final --json
# 2) 固化 SVG
$PY scripts/finalize_svg.py "$PROJ"
# 3) 导出 PPTX（带教师备注）
$PY scripts/svg_to_pptx.py "$PROJ" --with-notes --no-animations --pptx-structure flat
```

- 判成败看末行：`[POSTFLIGHT] status=passed quality_gate=passed slides=N`。
- stderr 的 `UnicodeDecodeError` 是读子进程输出线程的老毛病，**无害**。
- **真机实测**：内联 PowerShell 调 PowerPoint COM 导出 PNG
  （`$pres.Slides.Item($i).Export($f,'PNG',1920,1080)`），日志写纯 ASCII 路径再用 Read 读。

### P6 · 互动资源（两套，都单文件零依赖）

- `交互动画/` = **讲原理，看动作**，教师手动步进（上一步 / 下一步 / 重播 / ←→ / 空格 / R）
- `教学互动/` = **练判读，点选判对错 + 揭示答案与讲法**，对应 PPT「课堂互动 ①～⑩」页
  （本项目当前 10 个：9 个单项判读 + 1 个**跨元件迁移**练习。跨元件题每行只需给
  **非正解选项**配 `data-hint-*` 解析，正解项不配；静态断言要按「每行 2 条提示」计数，
  不能按「3 条」——否则误报 FAIL，而真机点选其实是过的）
- 两套都**教师手动、不自动播放**；答案区默认隐藏，先让学生说再点开
- 需要实物照时**图片 base64 内嵌**（缩到显示宽度、JPEG q82），保持零依赖
- 内容**全部取自** `design_spec.md` 各页 Content 与 `notes/` 备注，**不新增未经核实的事实**
- 验证：Playwright 驱本机浏览器**真机点击**（点主按钮 + 点所有 `.card/.opt/.step/.hot/.pick/input`），
  要求 **N/N 通过、0 控制台报错**；再出图拼总图目视核对版式

### P7 · 嵌入 PPTX

见 `pptx-embed-html-interactions`。本 skill 附可直接改用的脚本
`scripts/embed_html_objects.py`（改顶部 `PLAN` 与三处路径即可）。

⚠️ **嵌入对象数量一旦变化，三处必须同步**（缺一处即账实不符）：
① 脚本顶部映射表（1 基页号 → 文件名 → 图标标签）｜② `knowledge/INDEX.md` 的数量
｜③ 该页教师备注里对互动的提及。本项目由 16 → **17** 时即按此三处走。

### P8 · 迭代修订（每轮完整闭环，不要跳步）

**每一轮修订的标准动作**：

```
① 扫描确认现状（不假设） → ② 备份到 _backup/svg_<轮次>_<日期>/ 60 个 SVG
→ ③ 改 SVG 源 → ④ 质量门(--json) → ⑤ finalize_svg → ⑥ svg_to_pptx
→ ⑦ 真机实测抽页 → ⑧ 落盘 ppt/（升版本号）→ ⑨ 旧版进 _archive/ → ⑩ 前后对照图
```

已跑过的改动类型（可直接复用脚本思路）：
版面归位（章节导航 / 徽标）、文字块居中、触点符号重画、补配图、HTML 嵌入、
**页脚注文全册删除**、**整页改写（P60 综合任务页）**、**合规标注写回**。

⚠️ **改动前先问「要不要加页」——答案通常是不要**：本套每页页脚写死「P xx / 60」，
加 1 页要改全册 60 个 SVG 的页码并顺延其后各页编号（属高风险批量改动）。
**默认策略 = 不加页，把新内容压进现有页**：P60 把五档作业条从 58px 压成 30px 行，
腾出空间放综合任务蓝条 + 四张报告卡 + 互动提示框，**一条作业内容都没删**。

| # | 决策 | 结论与理由 |
|---|---|---|
| 1 | 视觉风格 | **浅色教学**（白底大留白 + 圆角卡片）：投影友好、印刷省墨 |

## 4 · 电气符号硬约定（GB/T 4728）

> 详版（含坐标、颜色、QF 三极结构）见 `references/electrical-symbols.md`。

**触点 = 静触点横线 + 动触点斜刀**（唯一的合法画法）：

- **静触点** = 与引线**垂直**的短横线（引线竖向 → 横线水平）
- **动触点** = 从引线端点斜出的**刀**
  - **常开**：刀翘起，刀尖沿引线方向差 **10–18px** 才碰到静触点横线 → 断开
  - **常闭**：刀**搭过**静触点横线（刀尖超出横线 **6–10px**）→ 接通
- **禁止**：①「圆点＋斜刀」；②「十字形」（长引线中间夹一条短横线，不代表任何触点）；
  ③ 同册常开常闭用两套互不相干的画法

**断路器 QF**：三极斜刀 + 每极脱扣标记 `×` + 一条水平联动虚线（`stroke-dasharray="6 5"`）。

**颜色语义**：`#059669` 接通 ｜ `#94A3B8` 断开 ｜ `#1D4ED8` 静触点与引线 ｜ `#EA580C` 互动/错误标记。

**审计纪律**：改符号前先做全册审计 —— ① 用脚本按几何特征统计 `<line>/<circle>/<path>`；
② 逐页读源码；③ 无头浏览器渲染 + PIL 裁剪放大；④ 与教材参照图对照。
**结论要落到「哪几页是自绘符号」的清单上，其余页（教材扫描图）不要动。**

**斜刀角度**：小于 20° 观感像横线，统一到 **25–32°**。

## 5 · 配图补充口径（AI 生成）

### 5.1 落点审计（不能只看「像有空白」）

1. 渲染候选页 → 找留白 → **逐页读源码确认**正文与页脚边界（渲染图会骗人：
   本次 P39/P06/P56 渲染看似可插，读源码发现正文+页脚已占满）
2. 章首页：留白在 `chapter-divider` **之后**
3. 场景页：无 `chapter-divider` 结构，**只能插在场景条内部**，且先量出正文字块**真实右缘**
   （如 P48 正文止于 `x≈896`），否则压字
4. 该页页脚写「配图为 AI 生成示意图，非实物照片」—— ⚠️ **2026-10-06 起页脚只留横线 + 页码**，
   这句 AI 标注是**页脚唯一允许保留的注文**（合规，不可删）。**新增/替换 AI 图必须同步该页标注**，
   并做「**图 ↔ 标注一一对应**」审计：脚本扫全册 `href="../images/scene_*_ai.png"` 与
   `配图为 AI 生成示意图` 逐页比对（本项目据此查出 **P53 有 AI 图却从未标注**，
   属人工记忆查不出的 v3 遗留漏标）

### 5.2 生成与后处理

- ImageGen 出图 **1536×1024**，**右下角带「AI生成」水印** → 按目标宽高比算裁切高度，
  **从底部切**（不能居中裁），原图留 `work/p1/_ai_raw/` 以便换比例时重裁（不重复消耗额度）
- 成品按目标尺寸 **×2 采样**三通道 crop；`crop=no-crop`（已在 lock 声明，不再二次裁）
- 目标底色是 `#F1F5F9` 时，把图四角**填成该底色**做圆角，**不要用 alpha 透明通道**

### 5.3 工程登记（双向闭合，缺一侧即报错）

| 位置 | 必须写 |
|---|---|
| `design_spec.md` §VIII | 一行：`Filename / Dimensions / Ratio / Purpose / Type / Image pattern / Crop Policy / Acquire Via / Status / Reference / text_policy / page_role` |
| `spec_lock.md` images | 一行：`- <key>: <path> \| source=ai \| crop=no-crop` |

- `Acquire Via` 与 `Status` **必须配对**：`ai→generated`｜`user→existing`｜`web→sourced`｜`formula→rendered`｜`placeholder→placeholder`；
  配对错报 `planned_image_status_mismatch`
- `Crop Policy` 只能是 `no-crop` / `adaptive`；`Image pattern` 不得留空
- 删图要**两侧同时删**，只删一边触发反向规则
- 采样倍率 `render_scale = 显示尺寸 ÷ 源图尺寸`：`>2.0` 报「会发虚」，`<0.25` 且源图 ≥1MiB 报「体积过大」；
  安全区间 **0.5×–4×**

## 6 · 注意事项（踩坑摘要）

> 完整 42 条见 `references/pitfalls.md`。下面是**每次都会踩**的六条。

1. **导出前必须刷新 final 质量报告**：`svg_quality_checker.py --stage final --json` ——
   漏 `--json` 只打印不落文件，导出报 `found stale`。
2. **批量改元素前先扫描占位**：不要假设某区域是空的。用 `data-pptx-bounds` 过滤目标区域，
   一次揪出全部冲突页（本次首轮漏扫 21 页徽标，改完又回退）。
3. **无头浏览器截图必须传绝对路径 URI**：`Path(相对路径).as_uri()` 抛
   `ValueError: relative path can't be expressed as a file URI`；改 `resolve().as_uri()`。
4. **OLE 包内文件名是 mbcs/GBK 编码**（不是 UTF-8）→ 校验 `.html` 扩展名要用
   `Path(p.decode("mbcs")).name.lower().endswith(".html")`，用 UTF-8 正则会得 0 命中。
5. **重导 PPT 后必须重跑嵌入脚本**，并把脚本里的 `DEFAULT_SRC` 换成**最新时间戳**那份导出件；
   否则 N 个嵌入对象全丢。
6. **PPTX 被预览/编辑器占用时 `os.replace` 报 `WinError 5 拒绝访问`** → 不硬覆盖，**升版本号**。

## 7 · 验证四级制（汇报时必须区分等级）

| 等级 | 手段 | 能证明什么 |
|---|---|---|
| L1 已读取 | 读源码 / 读设计规格 | 只证明「文件里是这么写的」 |
| L2 已技术核验 | 质量门 + `python-pptx` 回读 PPTX 几何 | 证明「转换后几何与源一致」 |
| L3 已渲染检查 | 无头浏览器出图 / PIL 裁剪放大 | 证明「看起来对」 |
| L4 已真机实测 | PowerPoint COM 导出 PNG + 目视 | 证明「真实软件里也对」 |

**宣称「完成」至少要到 L3；涉及交付物必须到 L4。**
每一轮的验收口径固定为：
`质量门 N/N Fully passed` + `postflight passed` + `slides/notesSlides/embeddings` 计数 +
`sha256 与导出件一致` + `真机导出 K 页目视通过`。

## 8 · 版本与文件管理纪律

- **改版以 SVG 源为准**：`svg_output/*.svg` → 质量门 → `finalize_svg` → `svg_to_pptx` → 覆盖 `ppt/`。
  **不要**用编辑器直接改 PPTX，否则源与成品分叉。
- `ppt/` **只留当前版**；历史版进 `ppt/_archive/`，命名 `<名称>_vN_pre_vM.pptx`。
- `work/` 留过程文件（SVG 源 / design_spec / spec_lock / 备注 / 脚本）；
  `knowledge/` 只放正式交付物。**生成过程文件不入知识库**。
- 每轮改动前备份整册 SVG：`_backup/svg_<轮次>_<日期>/`。
- **全册同步改动要有「差异断言」**：改完用脚本断言「**恰好 N 页有差异、每页恰好 K 处**」，
  其余页字节未变 —— 这是证明没误伤的硬证据（页脚注文删除即用此口径）。
- **页脚 `footer-note` 批量删除的稳妥写法**：正则
  `[ \t]*<text id="footer-note"[^>]*>.*?</text>[ \t]*\r?\n?`，用 `re.subn` 并
  **断言每页恰好命中 1 处**（防误删/漏删）；删完 `grep` 复核关键词在全册 0 残留。
- **合规标注写回**：从备份读原文，在 `</svg>` 前插回同一个 `id="footer-note"` 元素，
  保持 `data-pptx-role="footer"` 与坐标（`x=64 y=688 font-size=15 fill=#64748B`）。
- 收尾清理：渲染截图目录、`.svg_final.publish-*`、`.pptx-build-*`、过期导出件都清掉；
  **`_ai_raw/` 保留**（重裁比例要用，重生成要花额度）。
  ⚠️ `exports/` 常残留**时间戳中间件**（同一次迭代里反复跑的产物）→ 按**内容甄别**
  （slides 数 + 关键串）后清理，只留「未嵌导出件 + `_embedded.pptx`」。
